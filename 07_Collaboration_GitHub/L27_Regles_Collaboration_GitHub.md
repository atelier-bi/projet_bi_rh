# L27 — Règles de collaboration GitHub

**Projet :** Analyse des départs des salariés — BI RH  
**Module :** Atelier Business Intelligence  
**Sprint :** Sprint 1

## 1. Objectif

Ce document définit les règles de collaboration et de versionnement utilisées pour organiser le travail de l'équipe sur GitHub.

L'objectif est de centraliser les livrables, faciliter leur consultation et assurer la traçabilité des modifications.

## 3. Organisation du dépôt

Le dépôt GitHub `projet_bi_rh` regroupe les livrables dans des dossiers distincts :

- `01_Cadrage` : cadrage métier et Product Backlog initial.
- `02_Data` : données, exploration et diagnostic de qualité.
- `03_Planning` : planification GanttProject.
- `04_Scrum_Jira` : gestion Scrum et suivi Jira.
- `05_PowerBI` : fichiers et analyses Power BI.
- `06_Rapport_Sprint1` : rapport et présentation du sprint.
- `07_Collaboration_GitHub` : preuves et règles de collaboration.

## 4. Règles de collaboration proposées

Pour assurer une bonne organisation, l'équipe adoptera les règles suivantes :

1. Centraliser les livrables dans le dépôt GitHub commun.
2. Placer chaque fichier dans le dossier correspondant.
3. Utiliser des noms de fichiers explicites.
4. Vérifier les modifications avant de les enregistrer.
5. Rédiger des messages de commit compréhensibles.
6. Éviter de supprimer ou de remplacer le travail d'un autre membre sans concertation.
7. Informer les autres membres lorsqu'un livrable important est modifié.
8. Mettre à jour Jira pour refléter l'avancement réel des tâches.

## 5. Gestion des branches et des Pull Requests

Le dépôt dispose d'une branche principale nommée `principal`.

Une branche supplémentaire est visible dans le dépôt, mais son utilisation et les éventuelles Pull Requests restent à vérifier.

Pour la suite du projet, l'équipe pourra utiliser des branches distinctes pour les modifications importantes, puis vérifier les changements avant leur intégration dans la branche principale.

Le suivi des contributions repose également sur l'historique des commits GitHub.

## 6. Traçabilité

Les modifications enregistrées dans GitHub sont associées à un commit contenant un message, une date et un auteur.

La capture `L26_Historique_Commits.png` constitue une preuve de l'historique des modifications.

Les contributions individuelles des membres devront être vérifiées ou expliquées lorsque plusieurs personnes travaillent à partir d'un même compte.

## 7. Conclusion

Ces règles visent à améliorer l'organisation, la collaboration et la traçabilité des livrables du projet BI RH.

Elles pourront être adaptées pendant les prochains sprints selon les besoins de l'équipe.
